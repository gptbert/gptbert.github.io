做完一段视频以后，真正耗时间的工作往往才刚开始：字幕里的术语需要统一，某句译文不自然，配音要重录，口播中间还留着一段停顿。能否把这些修改接着做下去，比第一次生成得有多快更重要。

[BaoCut](https://github.com/gptbert/baocut) 把 AI 视频处理围绕一个可编辑的项目组织起来。转写、字幕、翻译、配音和画面修改进入同一条时间线，用户可以继续调整，再导出成片。它希望把自然语言操作接到日常剪辑中，让 AI 完成一部分工作，也让人随时接手。

本文按 2026 年 10 月 20 日可查的仓库文档与发行说明介绍功能，不把文档中的能力列表当作每个平台上的实测结果。`gptbert/baocut` 是 [JimLiu/baocut](https://github.com/JimLiu/baocut) 的 fork；下文先介绍项目的共同能力，再说明这个 fork 提供的 Intel Mac 预览版。

## 从一段已有素材开始

最直观的入口是一段访谈、课程或口播。BaoCut 可以调用本地语音识别模型，也可以连接在线接口，将语音变成带时间信息的文本。文档列出的本地选项包括 Whisper、Qwen3-ASR，以及支持说话人区分的 MOSS。识别片段可以随任务进度进入时间线，不必等整段录音全部处理完再开始查看。

有了带时间信息的文本，后续工作就有了共同的定位依据：字幕对应哪句话，某个观点出现在什么位置，剪短视频应该从哪里开始。模型和素材仍会影响识别质量，专有名词、重叠说话和嘈杂片段需要人工复核。

### 字幕、翻译和配音衔接起来

BaoCut 支持原文、译文和双语字幕，并按项目记住字幕样式。翻译由 Agent 逐句完成；译文需要修改时，可以回到对应句子继续编辑。

跨语言配音进一步串起翻译、人声与背景分离、逐句语音合成和音轨放置。文档列出的分离工具是 HTDemucs；语音可以来自预设音色或克隆音色。使用他人声音前应取得授权，最终还要听辨发音、情绪和句间衔接。

例如，把中文课程整理为带英文字幕的版本，可以先校正转写中的术语，再检查译文和断句，最后选择是否增加英文配音。这是按功能组合出的工作流示例，并非本文完成的一次实测。

### 用文本帮助口播剪辑

对口播素材，Agent 可以在时间线上处理口头填充词、长停顿、重录和说错后重新开始的部分，同时保留原始媒体。用户再检查衔接是否自然、语义是否完整，必要时继续手动调整。

同一份带时间信息的转写，也能用来整理章节、摘要、标题、博客草稿和短视频选段。时间戳方便回看原素材；它不能替代事实核查，也不能保证自动摘要没有遗漏。

## 从一句创意开始制作

已有素材并非唯一入口。BaoCut 文档列出 24 个内置场景模板及提示示例，覆盖讲解、产品发布、教程、数据故事和文字动效等方向。

其中一个实用思路是先写脚本和旁白，生成语音后再按旁白安排画面。这样可以用实际说话时长决定镜头节奏。需要静态画面时，可选择本地图像模型或在线服务。

动效则提供了代码入口：Agent 编写自包含的 HTML composition，将其作为代码包导入，烘焙成帧后放到时间线上。项目支持 `baocut/1` 和 `hyperframes/1` 两种约定，可用于人物姓名条、大数字、提示卡和品牌片头等元素。代码生成后仍需要预览，检查字体、换行、时长和画面边界。

## 人和 Agent 在同一个项目里工作

BaoCut 的一个关键设计，是让人工操作和 Agent 修改经过共同的命令入口、事务和撤销机制。用户拖动片段、Agent 调整字幕，都作用于同一个视频项目。

这使“修改其中一句”成为有明确对象的操作。编辑阶段可以针对局部修订；最终导出依然需要渲染，实际等待时间取决于素材、效果、模型和硬件。项目也强调限定 Agent 的作用范围、权限和预算，并为修改提供回执。实际使用时，仍应检查它改了什么，以及还有什么没有检查。

### 四个入口，共用一个 Runtime

| 入口 | 适合的用法 |
| --- | --- |
| 桌面应用 | 与 Agent 对话，在时间线预览、调整字幕和继续剪辑 |
| CLI | 将项目操作接入脚本，用结构化结果衔接后续步骤 |
| MCP 与 BaoCut skill | 让外部 Agent 调用同一套工具目录 |
| Web 客户端 | 通过 Runtime 生成的一次性链接，在浏览器打开视频编辑器 |

对已经有 Agent 工作环境的人，这种接口设计很有吸引力。BaoCut 提供视频项目与工具，外部 Agent 负责理解任务、选择工具和执行步骤。各入口共用 Runtime，但所用 Agent 引擎的兼容性和验证程度需查看当前文档。

## 本地模型带来选择，也带来条件

转写、语音合成、图像生成等能力可以选择本地模型或在线服务。模型下载默认使用 Hugging Face，也可切换 ModelScope 或自定义镜像；文档说明 ModelScope 缺少的少量文件仍会从 Hugging Face 获取，因此切换下载源不等于完全离线。

本地推理也不意味着整个任务都留在本机。外部 Agent 或在线模型可能接收相关文本和素材，使用前需要核对所选配置。在线服务的费用、模型下载空间和不同硬件上的速度，也应纳入工作流考虑。

安装包包含 Runtime 和原生 worker，但媒体分析、转写准备和导出还依赖外部 `ffmpeg`、`ffprobe`。Agent 功能需要安装并登录受支持的 Agent 引擎。普通使用者无需为了安装包额外配置 Node.js 和 Rust；它们属于源码开发环境。

## Intel Mac 用户需要单独看发行说明

上游 README 的 macOS 常规下载面向 macOS 14 及以上的 Apple Silicon；Windows 提供 CPU、CUDA 和 Vulkan 版本。Linux 目前按源码开发路径说明，不能由此推断已有 Linux 安装包。

这个 fork 另行发布了 [Intel Mac 3.8.0 预览版](https://github.com/gptbert/baocut/releases/tag/mac-intel-3.8.0-20261019)，提供 ZIP、DMG 和校验文件。发行说明记录了签名、公证、安装与 Runtime/worker 检查，同时明确其条件和验证范围：

- 面向 macOS 14 及以上的原生 x86_64 环境，没有自动更新源。
- Intel 不启用 MLX/Core ML；Whisper 在支持的环境使用 whisper.cpp Metal。
- Intel 不提供依赖 LiteRT 的语义搜索，不能把上游功能目录等同于 Intel 可用能力。
- 本次发行没有验证真实模型推理和完整剪辑、导出流程。

因此，可以将它作为 Intel 用户尝试 BaoCut 的入口，但不能把打包与公证通过解释为所有 AI 工作流已经实测通过。下载前请读对应版本的完整说明。

## 导出成片，也保留下一次修改的入口

BaoCut 支持导出 MP4、SRT/WebVTT、转写文本、音频，以及可移交的 `.baocut` 项目包。项目包包含视频快照、文档和资产版本，可以在另一台机器上重新打开继续编辑；它不包含原视频完整的事务和撤销历史。

这也解释了它的产品取向：成片是交付物，可编辑项目则保留了下一轮修改的空间。对课程、访谈、多语言内容和需要反复更新的视频，这个空间很有价值。

最后还需区分“源码可读”与许可范围。当前项目采用 BaoCut Community License 1.0。制作并销售视频内容，与销售、改名分发软件或提供托管服务，适用条件不同；第三方模型和素材也有各自许可，具体以仓库文件为准。

如果要开始尝试，建议先选一段短口播，完成转写、校正、字幕、预览和一次导出，再增加翻译或配音。一个能反复修改的小项目，比同时开启所有能力更容易看清这套工作流是否适合自己。
